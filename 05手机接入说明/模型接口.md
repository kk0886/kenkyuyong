# 新模型手机接入接口

## 输入
- 名称images，float32，NCHW：[1,3,416,416]，固定尺寸，batch1。
- 手机相机原图先纠正EXIF/传感器方向。按RGB排列，不是OpenCV默认BGR；像素除255，范围0到1，无额外均值方差标准化。
- 等比例缩放到可放入416正方形，余处填RGB(114,114,114)，不要直接拉伸。保留缩放比例和上下左右padding，用于还原。
- PT对照必须rect=False，以使用同样416正方形；此前训练演示的PT默认矩形推理与此固定ONNX输入不同，不能拿它逐像素直接比较。

## 输出
- output0：[1,37,3549]。37=4个框坐标+1个类别置信度+32个mask系数。框为416补边坐标中的中心x、中心y、宽、高，不是xyxy，也不是0到1坐标。单类分数已经可用于阈值，别再当成独立objectness乘一次。
- output1：[1,32,104,104]，32个掩膜原型。需要将每个实例的32系数与原型相乘，得到掩膜logit；阈值logit>0等价于sigmoid>0.5。
- 默认参考：conf=.25、NMS IoU=.7、mask阈值.5。导出没有内嵌NMS，手机端必须实现。
- 从掩膜原型空间去除对应补边，双线性恢复到原图尺寸，在还原后的检测框范围内裁剪；多个实例可合并为盲道前景。
- 具体四舍五入、padding、裁剪与插值示例见infer_onnx.py。不要把整张原型当作最终盲道掩膜。

## 本机验证与限制
两份ONNX通过onnx.checker并在ONNX Runtime CPU运行。两组各3张原图检查，统一输入后PT与参考ONNX合并掩膜IoU约96.5%到100%，不是完全逐像素相同；参考后处理采用OpenCV插值，与PyTorch以及浮点计算可能有边缘差异。数值记录见电脑端导出一致性检查.json。
这是导出及参考实现的小样本检查，不是识别准确率、手机实测或实时性能保证。未量化、未验证NNAPI/GPU委托；先用CPU正确性基线接通，再由手机同学测试具体机型。不要将本机推理时间声称手机延迟。

## 同学接入后应回传
机型/Android版本/运行后端，模型SHA，输入方向与尺寸，首次模型加载耗时、预处理/推理/后处理各耗时，若干原图与掩膜；区分冷启动与热运行。确认色彩与坐标正确后，再处理实时相机帧丢弃和性能。
